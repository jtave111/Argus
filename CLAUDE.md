# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Monorepo layout

Argus is a **polyglot monorepo**, organized by deployable unit. Directories use
**kebab-case** (`server`); the dot is reserved for Java packages (`com.argus.*`).
The only thing shared across components is the gRPC contract in `proto/argus.proto`.

```
argus/
├── proto/argus.proto     ← single source of truth for the agent↔server contract
├── server/               ← backend — Java 21 + Spring Boot + gRPC (Gradle module)
├── desktop/              ← desktop host — Java 21 + JavaFX (Gradle module; the "main")
│   └── renderer/         ←   the UI — React 18 + TS + Vite + Tailwind + Leaflet (npm)
├── agents/               ← native agents, grouped, NO shared code:
│   ├── linux/            ←   C++ + native gRPC (systemd, /proc)  [planned]
│   ├── windows/          ←   .NET/C# + grpc-dotnet (SCM, WMI)   [planned]
│   └── macos/            ←   native (launchd)                    [planned]
└── docs/
```

`server` + `desktop` form **one Gradle monorepo** (one `settings.gradle.kts`, one
`./gradlew`). The `desktop` host is the launcher — it **injects/serves** the React
**renderer** (`desktop/renderer`), which is **not** a web app: it has no public URL and
is served only on `127.0.0.1` (ephemeral port, **never exposed**). Model = Electron/Tauri:
native host (*main*) + embedded UI (*renderer*). This is the VS Code / DBeaver pattern. The visual identity
deliberately mirrors **ZombieKeeper-Client** (its `globals.css` was copied verbatim):
dark, monospaced, dense, square corners, **red accent**.

Each agent is **single-OS and native** (no cross-compilation, no shared agent code):
C++ talks to systemd directly, .NET talks to the Windows SCM directly. Do **not**
reintroduce a cross-platform abstraction layer for the agents — only `proto/` is shared.
Do **not** merge the frontend back into the server, or rewrite the UI in Swing (an earlier
Swing UI and a Tauri/SvelteKit prototype were both removed).

## Build Commands

```bash
# Backend + desktop host (root multi-module Gradle build).
./gradlew build                    # builds server + desktop
                                   # desktop transitively runs the desktop/renderer build
                                   # (npm install + vite) and embeds dist/ in its resources
./gradlew :server:bootRun    # run the backend (Spring Boot; needs PostgreSQL)
./gradlew :desktop:run       # open the desktop window (builds web if needed)
./gradlew :desktop:jpackageImage  # app-image (base for AppImage)
./gradlew :desktop:jpackage       # native installer (.deb/.exe/.dmg) — see docs/packaging.md

# Frontend alone (fast dev in a browser).
cd desktop/renderer && npm run dev        # http://localhost:5173  (dev only)
cd desktop/renderer && npm run build       # tsc + vite → dist/
```

The **server does not build the front** — `desktop` does, and it's still one root
command. Proto stubs are generated by the Gradle `com.google.protobuf` plugin in
`server` (reads `../proto` via `sourceSets`) — no manual `protoc`. Packaging is in
`docs/packaging.md`.

## Architecture

Argus is a remote infrastructure control panel. Agents run inside remote networks and **dial out** to the central server — no inbound ports needed (NAT/firewall traversal).

```
[Home / local server]                     [Remote network]
  Desktop App (JavaFX WebView + React)
  Argus Server (Java)  ◀──gRPC/TLS──────── Agent (C++ / .NET, native binary)
  PostgreSQL
```

### Key design decisions

**gRPC bidirectional stream** — `AgentService.Connect` in `proto/argus.proto` is a single persistent `stream AgentMessage` / `stream ServerCommand` channel. The agent sends telemetry (heartbeat, metrics, command results); the server pushes commands (service actions, shell). Avoid adding separate unary RPCs; extend the `oneof` payloads instead. The proto carries both `go_package` (legacy) and `java_package = com.argus.proto`.

**Two native agents, one contract** — one agent per OS in its native stack; they share nothing but `proto/argus.proto`. Add OS-level operations directly in each agent using its native API; never try to unify them in code.

**Agent owns the connection** — agent dials out, not the server. The agent holds the gRPC client connection and handles reconnect loops. The server is passive.

**Frontend renders from mock behind one seam** — `desktop/renderer/src/lib/mock.ts` holds a
disposable in-memory dataset mirroring the schema; all screens read via its query helpers.
When the backend API exists, swap `mock.ts` for real fetch/WS calls — screens don't change.

### Server stack (`server/`)

- **Java 21** with **Virtual Threads** (`spring.threads.virtual.enabled=true`).
- **Spring Boot 3.3.5**, Gradle (Kotlin DSL, wrapper 8.10.2). Main: `com.argus.ArgusServerApplication`.
- **gRPC** via `net.devh:grpc-server-spring-boot-starter` (`@GrpcService`, port 9090).
- **Web/WebSocket** via `spring-boot-starter-web` (port 8080) — the API the frontend will consume.
- **JOOQ** for data access; **Flyway** for migrations (`src/main/resources/db/migration`).

Java package map: `config` (beans) · `grpc` (`AgentService.Connect`) · `web` (REST/WS) ·
`service` (business logic + in-memory agent hub) · `domain` · `persistence` (JOOQ).

### Database

Schema is **Flyway migrations** in `server/src/main/resources/db/migration`
(`V1__*.sql` … `V13__*.sql`). Full reference: `docs/data-model.md`. Highlights:
Agent × Device split (V8); IPs/MACs live only on interfaces (V9); corporate hierarchy is
organization → branch → sector → network → device → agent, plus a user-management pillar
(`employees` with optional `user` login, roles, AD-ready) in V10–V13.

### Frontend (`desktop/renderer/`)

- **React 18 + TypeScript + Vite + Tailwind + Leaflet.** Design system copied from
  ZombieKeeper (`src/styles/globals.css`); see `desktop/renderer/CONTRACT.md` for the UI kit,
  helpers and screen conventions.
- Structure: `components/layout` (App router + Menubar/Sidebar/StatusBar), `components/screens`
  (one file per screen), `components/ui` (kit + `WorldMap` Leaflet), `lib` (`types`, `mock`, `fmt`).
- Screens: Dashboard, Devices, DeviceConsole (8 tabs incl. AnyDesk-style remote access),
  Agents, **AgentBuilder** (configure/generate agent installers), Services, Networks,
  Topology, Map (real Leaflet world map), Terminal, Employees(+detail), Users, Organization,
  Branches(+detail), Sectors, Audit, Profile (with personalization), Settings.

### Desktop host (`desktop/`)

- **Java 21 + JavaFX** (`javafx.web`). `DesktopMain` opens a `WebView`; `LocalWebServer`
  serves `desktop/renderer/dist` (embedded in resources) on `127.0.0.1`. Gradle tasks build the web
  and copy the dist into resources; `packageApp` wraps it with jpackage.

### Current state

Backend is a scaffold (Spring Boot shell + build + config; gRPC/web/domain/persistence not
yet implemented — empty packages via `package-info.java`). The **frontend is complete on
mock data** and builds green. The desktop host loads it. The agents are not created yet.
Feature roadmaps that need backend/DB work: `docs/roadmap-device-operations.md` and
`docs/roadmap-agent-builder.md`.
